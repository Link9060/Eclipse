# ECLIPSE

Browser-based stylized 3D adventure with 2D gameplay and an angled camera.

## Character creator v0.2 — GLB foundation

Run `python3 -m http.server 8000` and open http://localhost:8000, or visit https://link9060.github.io/Eclipse/. GitHub Actions deploys pushes to main when GitHub Pages uses the Actions source.

The character creator supports body frame, height, build, facial silhouette, skin, markings, eye light, 12 hairstyles, hair color, hood, cloak pattern, mantle, tunic, belt, wraps, boots and four material colors. State is versioned and persisted under `eclipse.character.v2`; v1 choices migrate automatically. Confirmation emits `eclipse:character-confirmed` with the Stage I kit and gameplay hood down.

## Art status

A first tailored, faceted art-blockout library is generated by `scripts/build-traveler.mjs`. It produces 149 independent GLB files covering all current mesh slots and options, with layered draped cloth, an open hood, hair locks, belt and pouch, facial planes and trim. These are unrigged, provisional authored-by-code surfaces, not production-quality sculpted art or a verified match to the concept. Hair/garment fit and facial detail still need visual iteration.

Run `node scripts/build-traveler.mjs` before serving locally. GitHub Actions runs this step automatically. Existing GLBs are deliberately retained, so artists can replace individual files with their own Blender exports without changing the renderer. Missing assets are reported explicitly.

## Architecture

- `src/character/state.js`: schema, validation, asset paths and local saves.
- `src/character/CharacterAssembler.js`: GLTFLoader, independent slot instances, material customization, race-safe loading.
- `src/creator.js`: controls, renderer, camera, confirmation event.
- `assets/characters/ASSET_SPEC.md`: exact conventions for art production.

The creator is a rest-pose art-blockout preview with GPU secondary motion. Shared animation playback, attachment fitting, collision, final artwork and the playable prologue are future work.

## Lightweight secondary motion

Open **Wind & motion preview** in the creator to control wind speed, direction, motion strength and simulated idle/walk/run speeds. These are preview controls, not body locomotion.

`src/character/SecondaryMotion.js` applies bounded, damped wind response and GPU vertex deformation to hair tips, cloak, loose tunic panels and mantle. Matching depth shaders deform directional-light shadows. No per-vertex CPU physics, per-frame mesh uploads, cloth collision or full simulation is used. Reduced-motion preferences disable the effect by default; the shader skips deformation when disabled. Actual FPS costs and clipping still require browser testing.

Future gameplay should call `assembler.motion.update(dt, localWindX, localWindZ, localVelocityX, localVelocityZ)` once per visible animated character per frame. Use `setEnabled(false)` for distant NPCs or low-quality mode. Current profiles assume the generated static meshes are in shared rest-space coordinates; future rigged assets need a rig-aware adapter.

Three.js is pinned to 0.160.1 and loaded from jsDelivr. Internet access and WebGL are needed for 3D rendering.
